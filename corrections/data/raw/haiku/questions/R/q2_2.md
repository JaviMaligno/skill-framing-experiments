## 2. Core change: convert at the API boundary

Assuming `apps/api/serializers.py` (adjust the path to match yours):

```python
# apps/api/serializers.py
from decimal import Decimal, ROUND_HALF_UP

from rest_framework import serializers

CENTS_PER_EUR = Decimal("100")


def cents_to_euros(cents: int) -> Decimal:
    return (Decimal(cents) / CENTS_PER_EUR).quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)


def euros_to_cents(euros: Decimal) -> int:
    return int((Decimal(euros) * CENTS_PER_EUR).quantize(Decimal("1"), rounding=ROUND_HALF_UP))


class PriceEurosField(serializers.Field):
    """Public API: euros as a decimal string (e.g. "12.50"). Storage: integer cents."""

    def to_representation(self, value: int) -> str:
        return str(cents_to_euros(value))

    def to_internal_value(self, data) -> int:
        try:
            euros = Decimal(str(data))
        except Exception as exc:
            raise serializers.ValidationError("Enter a valid euro amount.") from exc
        if euros < 0:
            raise serializers.ValidationError("Price cannot be negative.")
        if euros.as_tuple().exponent < -2:
            raise serializers.ValidationError("Price allows at most 2 decimal places.")
        return euros_to_cents(euros)
```

Then replace the existing price field on each public serializer:

```python
class ProductPublicSerializer(serializers.ModelSerializer):
    price = PriceEurosField(source="price_cents")

    class Meta:
        model = Product
        fields = ["id", "name", "price"]
```

Use a string, not a float, so the public API never loses cents to float rounding.

## 3. Decisions to make before shipping

- **Breaking change.** Every existing client reading `price` will get 100x larger values if it still expects cents. Options: (a) add a new field `price_eur` and deprecate `price`, (b) version the endpoint (`/api/v2/`), or (c) announce the change with a cutover date. I'd recommend (a), since it is the least disruptive and easy to roll back.
- **Billing.** You mentioned this touches pricing, so per the team conventions, put the new representation behind a feature flag. Checkout, invoices, and webhooks should keep using cents internally.
- **Writes.** If the API also accepts `price` on create/update, the `to_internal_value` path above handles that. Confirm the rounding rule (half-up is used here).
