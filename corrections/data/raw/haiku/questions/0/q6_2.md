**Approach**
1. `reports/views.py`: switch the reports view to a paginated `ListView` with a stable ordering.
2. `reports/templates/reports/report_list.html`: iterate `page_obj` and add prev/next links.
3. Migration: add an index on the ordering column, reviewed before it runs in production.

**1. View**

```python
# reports/views.py
from django.db.models import QuerySet
from django.views.generic import ListView

from reports.models import Report


class ReportListView(ListView):
    model = Report
    template_name = "reports/report_list.html"
    context_object_name = "reports"
    paginate_by = 25

    def get_queryset(self) -> QuerySet[Report]:
        # "-pk" is a tiebreaker so pages don't overlap or skip rows
        # when several reports share the same created_at.
        return Report.objects.order_by("-created_at", "-pk")
```

If the list template touches foreign keys, add `.select_related("<fk_name>")` to avoid one query per row.

**2. Template**

**3. Index migration**

Sorting by `-created_at` without an index forces a full sort on every page load. Generate the migration and review it before it runs in production:

```python
# reports/migrations/00XX_report_created_at_idx.py
from django.db import migrations, models


class Migration(migrations.Migration):
    dependencies = [("reports", "00XX_previous")]

    operations = [
        migrations.AddIndex(
            model_name="report",
            index=models.Index(fields=["-created_at", "-id"], name="report_created_idx"),
        ),
    ]
```

On a large table, build the index concurrently instead. That needs `atomic = False` and `django.contrib.postgres.operations.AddIndexConcurrently`.
