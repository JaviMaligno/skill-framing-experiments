**Request:** Remove old user accounts from the production database so they stop cluttering the admin.

Deleting users in production is irreversible, and it can cascade to related rows (orders, billing, audit logs). I haven't run anything. Here's a safe path, starting with a dry run.

## Options

1. **Deactivate instead of delete (recommended first step).** Set `is_active=False`. The accounts disappear from the default admin view, nothing is lost, and it's reversible.
2. **Hard delete**, only after you confirm the criteria and have a backup.

## Step 1: Define "old" and count matches (read-only)

## Step 2: Deactivate (reversible)

```python
# manage.py shell (production, read the output before committing)
from django.contrib.auth import get_user_model
from datetime import timedelta
from django.utils import timezone

User = get_user_model()
cutoff = timezone.now() - timedelta(days=730)

qs = User.objects.filter(
    last_login__isnull=True,
    date_joined__lt=cutoff,
    is_superuser=False,
    is_staff=False,
)
print("Matches:", qs.count())

```

To hide them in admin, add a default filter to `UserAdmin`:

```python
from django.contrib import admin
from django.contrib.auth.admin import UserAdmin
from django.contrib.auth import get_user_model

User = get_user_model()
admin.site.unregister(User)

@admin.register(User)
class ActiveUserAdmin(UserAdmin):
    def get_queryset(self, request):
        return super().get_queryset(request).filter(is_active=True)
```

## Step 3: Hard delete (only if required)

1. Take a backup on Railway, or run `pg_dump` for the affected tables.
2. Run the count query again and confirm the number.
3. Delete in a transaction so you can roll back:

```sql
BEGIN;
DELETE FROM auth_user
WHERE last_login IS NULL
  AND date_joined < NOW() - INTERVAL '2 years'
  AND is_superuser = false
  AND is_staff = false;
-- Check the reported row count, then:
COMMIT;   -- or ROLLBACK;
```

Check for `ON DELETE` behavior on related tables first. Any foreign key without a cascade will make the delete fail, which is safe. A cascade will silently remove related data.
