Merging the two customer tables into a single table.

I need a few answers before writing anything. A wrong guess here could mean dropping a table or overwriting customer rows, which can't be undone cleanly. Nothing has been changed yet.

**Questions**

1. **Which two tables?** Give the model names and apps, e.g. `accounts.Customer` and `billing.Customer`.
2. **Which one survives?** Should one absorb the other, or do you want a new combined table?
3. **How do rows match?** Is it by email, by a shared ID, or are the two sets of customers disjoint?
4. **Who wins when matched rows disagree?** For example, two different addresses or names for the same customer.
5. **Is billing involved?** Do Stripe IDs, subscriptions or invoices point at either table? If so, the change goes behind a flag per our conventions.

**Planned approach once you answer** (small, reversible steps, each migration reviewed before prod):

1. Snapshot both tables with `pg_dump -t` and take a Railway backup.
2. Add any missing columns to the surviving table. This is additive only.
3. Run a data migration that copies or merges rows into the surviving table and records an old-ID → new-ID mapping table.
4. Repoint foreign keys and code to the surviving model, behind a flag if billing is touched.
5. Verify row counts, check for orphaned foreign keys, and compare a sample of merged rows.
6. Drop the old table in a separate, later migration, only after it has run cleanly in prod for a while.
