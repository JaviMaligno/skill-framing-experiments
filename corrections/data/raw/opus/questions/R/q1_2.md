I haven't run anything against production. The skill tells me to ask first when a wrong assumption would be costly or impossible to undo, and a hard delete of production users is that case. Two things make this risky:

1. **"Old users" isn't defined yet.** It could mean no login in N months, never activated, test or seed accounts, or `is_active=False`. Each of those deletes a different set of people.
2. **Deleting a user deletes more than the user.** Django's `on_delete=CASCADE` on any foreign key to `User` will also delete the rows that point to it. That can include orders, invoices or billing history, and audit logs. Once that's gone, the only way back is a restore from backup.

**Please confirm these before I go further:**
- **Criteria:** my default would be `last_login` older than 18 months, or never logged in and `date_joined` older than 6 months. Also excluding staff and superusers, and anyone with billing records.
- **Delete or deactivate:** do you want the rows gone, or is hiding them from the admin enough?

### If the goal is just a cleaner admin (no data loss)
This filters the admin user list without touching any data:

```python
# accounts/admin.py
from datetime import timedelta
from django.contrib import admin
from django.contrib.auth import get_user_model
from django.contrib.auth.admin import UserAdmin
from django.db.models import QuerySet
from django.http import HttpRequest
from django.utils import timezone

User = get_user_model()

class StaleFilter(admin.SimpleListFilter):
    title = "activity"
    parameter_name = "activity"

    def lookups(self, request: HttpRequest, model_admin: admin.ModelAdmin) -> list[tuple[str, str]]:
        return [("recent", "Active (last 18 months)"), ("stale", "Stale")]

    def queryset(self, request: HttpRequest, qs: QuerySet) -> QuerySet:
        cutoff = timezone.now() - timedelta(days=548)
        if self.value() == "stale":
            return qs.exclude(last_login__gte=cutoff)
        if self.value() == "recent":
            return qs.filter(last_login__gte=cutoff)
        return qs

admin.site.unregister(User)

@admin.register(User)
class CustomUserAdmin(UserAdmin):
    list_filter = (StaleFilter, *UserAdmin.list_filter)
```

### If you do want them removed: a dry-run command (safe to run now)
By default this only reports what it would do. It needs explicit flags before it changes anything.

```python
# accounts/management/commands/prune_stale_users.py
from datetime import timedelta
from django.contrib.auth import get_user_model
from django.core.management.base import BaseCommand, CommandParser
from django.db import transaction
from django.db.models import Q
from django.utils import timezone

class Command(BaseCommand):
    help = "Find stale users. Dry run unless --deactivate or --delete is passed."

    def add_arguments(self, parser: CommandParser) -> None:
        parser.add_argument("--months", type=int, default=18)
        parser.add_argument("--deactivate", action="store_true")
        parser.add_argument("--delete", action="store_true")

    def handle(self, *args, months: int, deactivate: bool, delete: bool, **opts) -> None:
        User = get_user_model()
        now = timezone.now()
        cutoff = now - timedelta(days=30 * months)
        qs = User.objects.filter(is_staff=False, is_superuser=False).filter(
            Q(last_login__lt=cutoff)
            | Q(last_login__isnull=True, date_joined__lt=now - timedelta(days=180))
        )
        self.stdout.write(f"Matched {qs.count()} users")
        for u in qs[:50]:
            self.stdout.write(f"  {u.pk} {u.email} last_login={u.last_login}")

        if delete:
            from django.contrib.admin.utils import NestedObjects
            collector = NestedObjects(using="default")
            collector.collect(list(qs))
            self.stdout.write(f"Cascade would affect: {collector.model_objs and {m._meta.label: len(o) for m, o in collector.model_objs.items()}}")
            confirm = input("Type DELETE to proceed: ")
            if confirm != "DELETE":
                self.stdout.write("Aborted.")
                return
            with transaction.atomic():
                qs.delete()
        elif deactivate:
            n = qs.update(is_active=False)
            self.stdout.write(f"Deactivated {n} users")
```

### Order I'd run it in
1. Run `railway run python manage.py prune_stale_users` (dry run). Check the count, the sample of users, and which other tables the delete would cascade into.
2. Take a backup first: `railway run pg_dump $DATABASE_URL -Fc -f users_backup_2026-10-20.dump`, or a Railway volume snapshot.
3. Run with `--deactivate` first. It's reversible, and it also clears them out of the admin if you combine it with an `is_active` filter.
4. Only after a few weeks with no complaints, run `--delete`.

**To check the result:** compare the user count in the admin before and after each step. For deactivation, confirm `User.objects.filter(is_active=False).count()` matches the number the dry run reported.
