**Request:** make the public API return prices in euros instead of cents, on every endpoint that exposes `price`.

I need one answer before I write the final change, because a wrong guess here is expensive. If `price` silently goes from `1999` to `19.99` in place, every external client that still divides by 100 will show prices 100× too low. Nothing errors when that happens, and you can't undo it once clients have cached or charged on those values.

**The question:** should this be a breaking change to `price`, or a new field added alongside it?

- **A. Add a new field (my recommendation).** Keep `price` in cents, add `price_eur` as a decimal string (`"19.99"`), mark `price` as deprecated and remove it in a later version. This can be rolled back.
- **B. Release a new API version.** `/api/v2/` returns `price` in euros and `/api/v1/` stays in cents.
- **C. Change it in place.** Only safe if you control every consumer, for example if your own React front end is the only client.

While you decide, here is the groundwork for option A. It changes no existing behaviour.

**Approach**
1. Find every serializer and view that exposes a price: `grep -rn "price" --include=*.py */serializers*.py */api*/`.
2. Add one shared field class so the conversion lives in a single place.
3. Add `price_eur` to each public serializer, read from the same cents column. This needs no migration because the database stays in cents.
4. If any of these serializers are used by billing endpoints, put the new field behind a flag, per our billing convention.
5. Update the OpenAPI schema and changelog, and mark `price` as deprecated.

**Code**
```python
# core/api/fields.py
from decimal import Decimal
from rest_framework import serializers

class CentsToEurosField(serializers.Field):
    """Exposes an integer cents value as a 2-dp euro decimal string."""

    def to_representation(self, value: int) -> str:
        return str((Decimal(value) / Decimal(100)).quantize(Decimal("0.01")))

    def to_internal_value(self, data: str | int | float) -> int:
        try:
            amount = Decimal(str(data))
        except Exception as exc:
            raise serializers.ValidationError("Invalid euro amount.") from exc
        if amount.as_tuple().exponent < -2:
            raise serializers.ValidationError("At most 2 decimal places.")
        return int(amount * 100)
```

```python
# products/serializers.py (repeat for each public serializer that exposes price)
from core.api.fields import CentsToEurosField

class ProductSerializer(serializers.ModelSerializer):
    price_eur = CentsToEurosField(source="price", read_only=True)

    class Meta:
        model = Product
        fields = [..., "price", "price_eur"]
```

The new field returns decimal strings, not floats, so there are no rounding errors like `19.990000001`.
