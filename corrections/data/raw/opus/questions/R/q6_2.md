**Request:** Paginate the reports list so `/reports` stops loading every report in one request.

**Assumptions** (I can't see the code from here, so adjust names as needed):
- The React `/reports` page fetches from a Django REST Framework endpoint, e.g. `GET /api/reports/`, backed by a `Report` model.
- Pagination should be page-number based (`?page=2`), 25 per page, newest first.
- Nothing here touches billing, so no feature flag is needed. The change is reversible.

## Approach
1. **Backend:** Add a pagination class to the reports list view, with stable ordering and `select_related` to avoid N+1 queries.
2. **Database:** Add an index on the ordering column if one doesn't exist. This is a small migration that needs review before it runs in prod.
3. **Frontend:** Read the paginated response shape and add prev/next controls.

## 1. Backend

`reports/pagination.py`
```python
from rest_framework.pagination import PageNumberPagination


class ReportPagination(PageNumberPagination):
    page_size: int = 25
    page_size_query_param: str = "page_size"
    max_page_size: int = 100
```

`reports/views.py`
```python
from django.db.models import QuerySet
from rest_framework import generics

from .models import Report
from .pagination import ReportPagination
from .serializers import ReportSerializer


class ReportListView(generics.ListAPIView):
    serializer_class = ReportSerializer
    pagination_class = ReportPagination

    def get_queryset(self) -> QuerySet[Report]:
        return (
            Report.objects
            .select_related("author")      # adjust to the FKs the serializer touches
            .order_by("-created_at", "-id")  # stable ordering is required for paging
        )
```

If the view is currently a plain `APIView` returning `Response(serializer.data)`, replace it with the class above. The URL route stays the same.

The response shape changes from `[...]` to:
```json
{ "count": 1234, "next": "...?page=2", "previous": null, "results": [...] }
```
Any other consumer of this endpoint must be updated too. Search the repo for `/api/reports` before merging.

## 3. Frontend

`ReportsPage.tsx`
```tsx
import { useEffect, useState } from "react";

type Report = { id: number; title: string; created_at: string };
type Page<T> = { count: number; next: string | null; previous: string | null; results: T[] };

const PAGE_SIZE = 25;

export default function ReportsPage() {
  const [page, setPage] = useState(1);
  const [data, setData] = useState<Page<Report> | null>(null);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    fetch(`/api/reports/?page=${page}`, { signal: controller.signal })
      .then((r) => r.json())
      .then(setData)
      .catch((e) => { if (e.name !== "AbortError") console.error(e); })
      .finally(() => setLoading(false));
    return () => controller.abort();
  }, [page]);

  const totalPages = data ? Math.max(1, Math.ceil(data.count / PAGE_SIZE)) : 1;

  return (
    <div>
      {loading && <p>Loading…</p>}
      <ul>
        {data?.results.map((r) => <li key={r.id}>{r.title}</li>)}
      </ul>
      <nav>
        <button disabled={!data?.previous} onClick={() => setPage((p) => p - 1)}>Previous</button>
        <span> Page {page} of {totalPages} </span>
        <button disabled={!data?.next} onClick={() => setPage((p) => p + 1)}>Next</button>
      </nav>
    </div>
  );
}
```

Optional: sync `page` to the URL (`?page=`) with your router so refresh and back-button keep the position.

## Verify
- **API:** `curl "localhost:8000/api/reports/?page=1"` returns 25 results plus `count`, `next` and `previous`. Check that `?page=9999` returns 404 and that `?page_size=500` is capped at 100.
- **Queries:** With Django Debug Toolbar, or `assertNumQueries` in a test, the list should run a constant number of queries (count + page), not one per report.
- **Test:**
  ```python
  def test_reports_paginated(api_client, report_factory) -> None:
      report_factory.create_batch(30)
      res = api_client.get("/api/reports/")
      assert res.status_code == 200
      assert res.data["count"] == 30
      assert len(res.data["results"]) == 25
      assert res.data["next"] is not None
  ```
- **UI:** `/reports` loads quickly, Next/Previous work, and buttons disable correctly on the first and last page.
- **Index:** After migrating, run `EXPLAIN ANALYZE` on the page query and confirm it uses `report_created_id_idx` instead of a seq scan plus sort.

If the reports table gets very large (hundreds of thousands of rows or more), `COUNT(*)` and deep `OFFSET`s will get slow. At that point, switch to DRF's `CursorPagination` with `ordering = ("-created_at", "-id")`, which drops total page counts but stays fast at any depth.
