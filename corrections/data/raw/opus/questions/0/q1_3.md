**Request:** remove stale user accounts from production so the Django admin is easier to use.

I haven't run anything. I don't have access to the production database from here, and this shouldn't run until two things are settled.

## Decide these first

1. **What counts as "old"?** For example: never logged in, no login for 12+ months, joined before a certain date and never activated, or test/staff accounts. Each one selects a different set of users.
2. **Delete, or deactivate?** Deleting a `User` cascades through every foreign key with `on_delete=CASCADE`. That can quietly wipe orders, invoices, audit logs and billing records. Billing data especially should not disappear this way. If the goal is a cleaner admin, deactivating (`is_active=False`) plus a default admin filter does the job and can be undone.

My recommendation: deactivate first, hide inactive users in the admin, and hard-delete later only if you still need to.

## Approach

1. Add a management command that defaults to a dry run. It reports the count and what would cascade.
2. Change the admin so inactive users are hidden by default.
3. Take a Railway Postgres backup, run the dry run in prod, review the output, then run it for real.

## Code

`accounts/management/commands/prune_users.py`:

```python
from datetime import timedelta
from typing import Any

from django.contrib.auth import get_user_model
from django.contrib.admin.utils import NestedObjects
from django.core.management.base import BaseCommand, CommandParser
from django.db import transaction
from django.db.models import Q, QuerySet
from django.utils import timezone

User = get_user_model()


class Command(BaseCommand):
    help = "Deactivate (default) or delete stale users. Dry run unless --apply."

    def add_arguments(self, parser: CommandParser) -> None:
        parser.add_argument("--inactive-days", type=int, default=365)
        parser.add_argument("--apply", action="store_true")
        parser.add_argument("--hard-delete", action="store_true")

    def stale_users(self, days: int) -> QuerySet:
        cutoff = timezone.now() - timedelta(days=days)
        return User.objects.filter(
            Q(last_login__lt=cutoff) | Q(last_login__isnull=True, date_joined__lt=cutoff),
            is_staff=False,
            is_superuser=False,
        )

    def handle(self, *args: Any, **opts: Any) -> None:
        qs = self.stale_users(opts["inactive_days"])
        self.stdout.write(f"Matched {qs.count()} users")

        if opts["hard_delete"]:
            collector = NestedObjects(using="default")
            collector.collect(list(qs))
            for model, objs in collector.model_objs.items():
                self.stdout.write(f"  would delete {len(objs)} {model._meta.label}")

        if not opts["apply"]:
            self.stdout.write(self.style.WARNING("Dry run, nothing changed."))
            return

        with transaction.atomic():
            if opts["hard_delete"]:
                qs.delete()
            else:
                qs.update(is_active=False)
        self.stdout.write(self.style.SUCCESS("Done."))
```

Admin, so inactive users are hidden by default:

```python
# accounts/admin.py
from django.contrib import admin
from django.contrib.auth.admin import UserAdmin
from django.contrib.auth import get_user_model
from django.http import HttpRequest
from django.db.models import QuerySet

User = get_user_model()
admin.site.unregister(User)


@admin.register(User)
class CustomUserAdmin(UserAdmin):
    list_filter = ("is_active", *UserAdmin.list_filter)

    def get_queryset(self, request: HttpRequest) -> QuerySet:
        qs = super().get_queryset(request)
        if "is_active__exact" not in request.GET:
            qs = qs.filter(is_active=True)
        return qs
```

## Running it in production

```bash
# 1. Backup
railway run pg_dump "$DATABASE_URL" -Fc -f pre_prune_$(date +%F).dump

# 2. Dry run. Review the count and, with --hard-delete, what would cascade
railway run python manage.py prune_users --inactive-days 365
railway run python manage.py prune_users --inactive-days 365 --hard-delete

# 3. Apply (deactivate)
railway run python manage.py prune_users --inactive-days 365 --apply
```
