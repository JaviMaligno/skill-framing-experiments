**Request:** make the public API return and accept `price` in euros instead of cents, everywhere it shows up.

I haven't touched any code. This session doesn't include the Django or React repo (the working directory is `skill-framing-experiments/corrections`), so the code below is a pattern for you to apply, not a diff. Before you apply it, two things to settle:

1. **Changing what an existing field means is the riskiest way to do this.** Any client still reading `price: 1999` as cents would read `price: "19.99"` as 19.99 cents, or fail to parse it. Nothing errors loudly, so this kind of mistake can go unnoticed for weeks. The safer route is to put the new meaning behind an API version (or a new field name like `price_eur`) and keep v1 as cents until clients have moved. Prices touch billing, so per our conventions this also goes behind a flag.
2. **"Everywhere" should mean the API only, not the database.** Keep storing integer cents. Converting at the serializer boundary is small and easy to reverse, and avoids float rounding. If you did mean changing the database column too, say so; that's a separate, bigger migration.

## Approach

1. Find every place `price` crosses the API boundary: serializers, any hand-built `JsonResponse` or dicts, webhook payloads, CSV/exports, the OpenAPI schema, and tests.
2. Add one `EuroAmountField` serializer field that converts cents to euros on output and euros to cents on input.
3. Use it in the v2 serializers. v1 keeps returning cents.
4. Gate v2 behind a flag, then update the React client to call v2 and drop its `/ 100` formatting.
5. Announce a deprecation date for v1 and remove it later.

## The field

```python
# api/fields.py
from decimal import Decimal, ROUND_HALF_UP
from typing import Any

from rest_framework import serializers


class EuroAmountField(serializers.DecimalField):
    """Stored as integer cents; exposed as a decimal euro string, e.g. "19.99"."""

    def __init__(self, **kwargs: Any) -> None:
        kwargs.setdefault("max_digits", 12)
        kwargs.setdefault("decimal_places", 2)
        kwargs.setdefault("coerce_to_string", True)
        super().__init__(**kwargs)

    def to_representation(self, value: int) -> str:
        return super().to_representation(Decimal(value) / Decimal(100))

    def to_internal_value(self, data: Any) -> int:
        euros: Decimal = super().to_internal_value(data)  # rejects >2 decimal places
        return int((euros * 100).quantize(Decimal("1"), rounding=ROUND_HALF_UP))
```

The field returns a **string** (`"19.99"`), not a JSON number, so no client ever parses the price as a float.

## Versioned serializers

```python
# api/serializers.py
from rest_framework import serializers

from api.fields import EuroAmountField
from catalog.models import Product


class ProductSerializerV1(serializers.ModelSerializer):
    class Meta:
        model = Product
        fields = ["id", "name", "price"]  # integer cents, unchanged


class ProductSerializerV2(ProductSerializerV1):
    price = EuroAmountField(source="price")  # model field holds cents

    class Meta(ProductSerializerV1.Meta):
        pass
```

```python
# api/views.py
from django.conf import settings
from rest_framework import viewsets
from rest_framework.serializers import BaseSerializer


class ProductViewSet(viewsets.ModelViewSet):
    def get_serializer_class(self) -> type[BaseSerializer]:
        if self.request.version == "v2" and settings.FEATURE_API_PRICE_EUROS:
            return ProductSerializerV2
        return ProductSerializerV1
```

```python
# settings.py
REST_FRAMEWORK = {
    # ...
    "DEFAULT_VERSIONING_CLASS": "rest_framework.versioning.URLPathVersioning",
    "DEFAULT_VERSION": "v1",
    "ALLOWED_VERSIONS": ["v1", "v2"],
}
FEATURE_API_PRICE_EUROS = env.bool("FEATURE_API_PRICE_EUROS", default=False)
```

If you already use a flag library (waffle or similar), swap the settings check for it. Do the same for every serializer, webhook builder and export that your `rg` search turns up.

## Verify

```python
# api/tests/test_euro_amount_field.py
import pytest
from rest_framework.exceptions import ValidationError

from api.fields import EuroAmountField


@pytest.mark.parametrize("cents,euros", [(0, "0.00"), (1, "0.01"), (1999, "19.99"), (100000, "1000.00")])
def test_round_trip(cents: int, euros: str) -> None:
    f = EuroAmountField()
    assert f.to_representation(cents) == euros
    assert f.to_internal_value(euros) == cents


def test_rejects_sub_cent() -> None:
    with pytest.raises(ValidationError):
        EuroAmountField().to_internal_value("19.999")
```

- Use API tests to check that `/api/v1/products/` still returns `1999` and `/api/v2/products/` returns `"19.99"`, with the flag both on and off.
