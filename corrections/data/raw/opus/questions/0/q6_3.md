Add server-side pagination to the reports list so `/reports` loads one page at a time instead of every report.

I don't have the app code in this workspace, so names like `ReportViewSet`, `Report.created_at` and `ReportsPage.tsx` are guesses. Swap in your real ones.

## Approach

1. **Backend:** paginate the reports API endpoint with a stable ordering.
2. **Database:** add an index on the ordering column so each page query stays fast.
3. **Frontend:** have the reports page request one page at a time and show prev/next controls.
4. The response shape changes from a bare list to `{count, next, previous, results}`, so ship the backend and frontend together. If anything else uses this endpoint, see the note at the end.

## 1. Backend (Django REST Framework)

`reports/pagination.py`

```python
from rest_framework.pagination import PageNumberPagination


class ReportPagination(PageNumberPagination):
    page_size: int = 25
    page_size_query_param: str = "page_size"
    max_page_size: int = 100
```

`reports/views.py`

```python
from django.db.models import QuerySet
from rest_framework import viewsets

from .models import Report
from .pagination import ReportPagination
from .serializers import ReportSerializer


class ReportViewSet(viewsets.ReadOnlyModelViewSet):
    serializer_class = ReportSerializer
    pagination_class = ReportPagination

    def get_queryset(self) -> QuerySet[Report]:
        # Stable ordering is required: without a unique tiebreaker,
        # rows can repeat or disappear between pages.
        return (
            Report.objects
            .select_related("author")  # adjust to whatever the serializer touches
            .order_by("-created_at", "-id")
        )
```

**If the view is a plain Django view rather than DRF:**

```python
from django.core.paginator import Paginator
from django.http import HttpRequest, JsonResponse


def report_list(request: HttpRequest) -> JsonResponse:
    qs = Report.objects.order_by("-created_at", "-id")
    page_size = min(int(request.GET.get("page_size", 25)), 100)
    page = Paginator(qs, page_size).get_page(request.GET.get("page"))
    return JsonResponse({
        "count": page.paginator.count,
        "page": page.number,
        "num_pages": page.paginator.num_pages,
        "results": [serialize_report(r) for r in page.object_list],
    })
```

## 3. Frontend

`ReportsPage.tsx`

```tsx
import { useEffect, useState } from "react";

type Report = { id: number; title: string; created_at: string };
type Page<T> = { count: number; next: string | null; previous: string | null; results: T[] };

const PAGE_SIZE = 25;

export default function ReportsPage() {
  const [page, setPage] = useState(1);
  const [data, setData] = useState<Page<Report> | null>(null);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    const ctrl = new AbortController();
    setLoading(true);
    fetch(`/api/reports/?page=${page}&page_size=${PAGE_SIZE}`, { signal: ctrl.signal })
      .then((r) => r.json())
      .then(setData)
      .catch((e) => { if (e.name !== "AbortError") throw e; })
      .finally(() => setLoading(false));
    return () => ctrl.abort();
  }, [page]);

  const totalPages = data ? Math.max(1, Math.ceil(data.count / PAGE_SIZE)) : 1;

  return (
    <div>
      {loading && <p>Loading…</p>}
      <ul>{data?.results.map((r) => <li key={r.id}>{r.title}</li>)}</ul>
      <nav>
        <button disabled={!data?.previous} onClick={() => setPage((p) => p - 1)}>Previous</button>
        <span> Page {page} of {totalPages} </span>
        <button disabled={!data?.next} onClick={() => setPage((p) => p + 1)}>Next</button>
      </nav>
    </div>
  );
}
```

Optionally, keep `page` in the URL (`?page=3`) via your router's search params so pages survive refreshes and can be shared.

## Verify

- **API:** `curl "localhost:8000/api/reports/?page=2&page_size=25"` returns 25 results, the correct `count`, and `next`/`previous` links.
- **Edge cases:**
  - `?page=9999` returns a 404 in DRF. The plain-Django `get_page` clamps to the last page instead.
  - `page_size=1000` gets capped at 100.
- **No duplicates or gaps:** walk all pages in a test and assert the IDs you collect equal `Report.objects.count()` with no repeats.
- **Query plan:** in a staging shell, run `EXPLAIN ANALYZE` on the page query and confirm it uses `report_created_id_idx`. Use `assertNumQueries` to confirm there's no N+1 per row.
- **UI:** the first load is fast, and prev/next are disabled at the boundaries.

## Note on other consumers

If something else (an export job, another page) relies on the endpoint returning the full list, don't break it. Either keep the old unpaginated route for it, or make pagination opt-in with `?page=` and remove the old behavior once nothing depends on it.
