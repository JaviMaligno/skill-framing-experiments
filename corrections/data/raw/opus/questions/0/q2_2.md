I'm changing the public API so `price` is returned and accepted in euros instead of integer cents, on every endpoint that exposes it.

I couldn't open the repo from this session, so I haven't seen your actual code. The code below assumes DRF and should be adapted to it.

**This breaks existing API clients.** Anyone reading `price: 1999` today will start getting `"19.99"`, with no error to warn them. If this API touches billing (checkout, invoices), your conventions say it goes behind a flag. I've written the plan so new clients opt in and old ones keep cents until you switch the default.

## Approach

1. **Leave the database in cents.** Integer cents is the right way to store money, so no migration and nothing for production review. Only the API's input and output change.
2. **Send euros as a decimal string** (`"19.99"`), not a float like `19.99`, which can't be stored exactly. Stripe-style APIs and most money APIs do the same.
3. **Add one reusable serializer field** and use it on every serializer that has `price`.
4. **Gate it by API version** (DRF `AcceptHeaderVersioning`): `v1` keeps cents, `v2` returns euros. Change the default once clients have moved over.
5. **Update the React front end** wherever it divides or multiplies by 100.

Order: field and tests → serializers → versioning → front end → docs and changelog → change the default.

**2. Reusable field** (`core/api/fields.py`)

```python
from decimal import Decimal, InvalidOperation, ROUND_HALF_UP
from typing import Any

from rest_framework import serializers

_CENT = Decimal("0.01")


class EurosFromCentsField(serializers.Field):
    """Stores integer cents in the model; shows a 2-dp euro string in the API."""

    default_error_messages = {
        "invalid": "Enter a valid euro amount, e.g. \"19.99\".",
        "precision": "Euro amounts may have at most 2 decimal places.",
        "negative": "Price must not be negative.",
    }

    def to_representation(self, value: int) -> str:
        return str((Decimal(value) / 100).quantize(_CENT))

    def to_internal_value(self, data: Any) -> int:
        try:
            euros = Decimal(str(data))
        except (InvalidOperation, ValueError, TypeError):
            self.fail("invalid")
        if not euros.is_finite():
            self.fail("invalid")
        if euros != euros.quantize(_CENT):
            self.fail("precision")
        if euros < 0:
            self.fail("negative")
        return int((euros * 100).to_integral_value(rounding=ROUND_HALF_UP))
```

**3. Serializers** (repeat for each one the `rg` search finds)

```python
from rest_framework import serializers

from core.api.fields import EurosFromCentsField
from products.models import Product


class ProductSerializerV1(serializers.ModelSerializer):
    class Meta:
        model = Product
        fields = ["id", "name", "price"]  # price = int cents (legacy)


class ProductSerializerV2(ProductSerializerV1):
    price = EurosFromCentsField(source="price")  # model field stays cents

    class Meta(ProductSerializerV1.Meta):
        pass
```

**4. Versioning** (`settings.py` and views)

```python

    # ...

    "DEFAULT_VERSION": "1",          # change to "2" when clients have moved

```

```python
from rest_framework import serializers, viewsets


class ProductViewSet(viewsets.ModelViewSet):
    queryset = Product.objects.all()

    def get_serializer_class(self) -> type[serializers.Serializer]:
        return ProductSerializerV2 if self.request.version == "2" else ProductSerializerV1
```

**5. Front end:** send `Accept: application/json; version=2` from the API client. Then remove the `/ 100` and `* 100` conversions the search finds. Format with `Intl.NumberFormat("es-ES", { style: "currency", currency: "EUR" }).format(Number(price))` and send prices back as strings.

**6. Docs:** update the OpenAPI schema (`type: string, format: decimal, example: "19.99"`) and add a changelog entry with the date the default will change.

## How to verify

- **Unit tests for the field:**
  - `1999` → `"19.99"`, `0` → `"0.00"`, `5` → `"0.05"`.
  - `"19.99"` → `1999`.
  - `"19.999"` is rejected (more than 2 decimals).
  - `"-1"`, `"abc"` and `"NaN"` are rejected.
- **Round trip:** a v2 POST with `"price": "19.99"` stores `1999` in the database.
- **Both versions on one product:** a request without a version header returns `1999`, and one with `Accept: ...; version=2` returns `"19.99"`.
- **Coverage check:** `rg -n "price" ... serializers` should show no serializer exposing `price` without a v2 version.
- **Front end:** the prices shown before and after the switch match exactly in the cart, checkout and invoice.
- **Before changing the default:** check the access logs for clients still calling without `version=2`.

If you want the hard switch with no versioning and know every client, skip step 4. Put `EurosFromCentsField` straight on the existing serializers and release it together with the front-end change. Billing still needs the flag either way.
