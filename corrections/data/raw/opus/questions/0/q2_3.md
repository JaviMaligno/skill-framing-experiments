## Two decisions to make first

1. **Changing the unit of an existing field breaks every client without warning.** A client that sends `price: 1999` meaning €19.99 would now be read as €1,999.00, and nothing would error. That's a billing risk. I'd do it one of two ways:
   - **Additive (recommended):** add a `price_eur` field, mark `price` (cents) as deprecated, and remove it on an announced date.
   - **Versioned:** keep `price` but return euros only under API `v2`. `v1` keeps returning cents.

   Either way, ship it behind a flag, since it touches billing.
2. **Leave the database alone.** Keep storing integer cents. Only what the API shows and accepts changes, so there's no migration. Send euros as a **decimal string** like `"19.99"`, not a float.

**2. The field** (`api/fields.py`)
```python
from decimal import Decimal, InvalidOperation
from typing import Any

from rest_framework import serializers

CENT = Decimal("0.01")


class CentsAsEurosField(serializers.Field):
    """Stores integer cents; exposes a decimal-string euro amount, e.g. "19.99"."""

    def to_representation(self, value: int) -> str:
        return str((Decimal(value) / 100).quantize(CENT))

    def to_internal_value(self, data: Any) -> int:
        if isinstance(data, float):
            raise serializers.ValidationError("Send the amount as a string, e.g. \"19.99\".")
        try:
            amount = Decimal(str(data))
        except InvalidOperation:
            raise serializers.ValidationError("Must be a decimal euro amount.")
        if not amount.is_finite() or amount < 0:
            raise serializers.ValidationError("Must be a non-negative euro amount.")
        if amount != amount.quantize(CENT):
            raise serializers.ValidationError("At most 2 decimal places.")
        return int(amount * 100)
```
