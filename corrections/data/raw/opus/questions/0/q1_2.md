**Request:** remove stale user accounts from production so the Django admin is easier to use.

I haven't run anything against production, and I don't have a database connection from here anyway. Before anyone deletes data, two things need settling.

## What needs deciding first

1. **What counts as "old"?** For example: never logged in and joined more than 12 months ago, or no login in 2 years, or `is_active=False`. Each rule deletes a different set of people. Tell me the rule you want.
2. **Deleting users cascades.** Django's `User.delete()` follows every `ForeignKey(on_delete=CASCADE)`. That can wipe orders, audit logs, and billing or invoice records, which we may be legally required to keep. Any FK set to `PROTECT` will make the delete fail partway through.

Since the problem is clutter in the admin, the smallest reversible fix is to **hide them instead of deleting them**. Only hard-delete if you have another reason to.

## Option A (recommended): deactivate and filter the admin

```python
# accounts/admin.py
from django.contrib import admin
from django.contrib.auth.admin import UserAdmin
from django.contrib.auth import get_user_model
from django.http import HttpRequest
from django.db.models import QuerySet

User = get_user_model()
admin.site.unregister(User)

@admin.register(User)
class ActiveFirstUserAdmin(UserAdmin):
    list_filter = ("is_active", *UserAdmin.list_filter)

    def get_queryset(self, request: HttpRequest) -> QuerySet:
        qs = super().get_queryset(request)
        # Hide inactive users unless the filter is explicitly used
        if "is_active__exact" not in request.GET:
            qs = qs.filter(is_active=True)
        return qs
```

## Option B: a management command for deactivation or deletion, dry-run by default

```python
# accounts/management/commands/prune_users.py
from datetime import timedelta
from django.contrib.auth import get_user_model
from django.contrib.admin.utils import NestedObjects
from django.core.management.base import BaseCommand, CommandParser
from django.db import router, transaction
from django.db.models import Q
from django.utils import timezone

User = get_user_model()

class Command(BaseCommand):
    help = "Deactivate (or delete) stale users. Dry run unless --apply."

    def add_arguments(self, parser: CommandParser) -> None:
        parser.add_argument("--days", type=int, required=True)
        parser.add_argument("--apply", action="store_true")
        parser.add_argument("--hard-delete", action="store_true")

    def handle(self, *args: object, days: int, apply: bool, hard_delete: bool, **opts: object) -> None:
        cutoff = timezone.now() - timedelta(days=days)
        qs = User.objects.filter(
            Q(last_login__lt=cutoff) | Q(last_login__isnull=True, date_joined__lt=cutoff),
            is_staff=False, is_superuser=False,
        )
        self.stdout.write(f"{qs.count()} users match (cutoff {cutoff:%Y-%m-%d})")

        if hard_delete:
            collector = NestedObjects(using=router.db_for_write(User))
            collector.collect(list(qs[:500]))
            for model, objs in collector.model_objs.items():
                self.stdout.write(f"  would cascade: {model._meta.label} x{len(objs)}")
            if collector.protected:
                self.stdout.write(self.style.ERROR(f"  {len(collector.protected)} PROTECTED objects block deletion"))

        if not apply:
            self.stdout.write("Dry run. Pass --apply to execute.")
            return

        with transaction.atomic():
            if hard_delete:
                qs.delete()
            else:
                qs.update(is_active=False)
        self.stdout.write(self.style.SUCCESS("Done."))
```

## How to verify

- Before running, the dry-run count should match a manual `SELECT count(*)` using the same rule.
- Afterwards, the admin user list should show only active users, and you can still find the inactive ones by filtering on `is_active`.
- If you hard-delete, check that billing and invoice row counts haven't changed.
