**Request:** a function that turns an invoice title like `"Factura #2026-014 — Acme S.L. (Q3)"` into a URL-safe slug like `factura-2026-014-acme-sl-q3`.

## Approach

1. Add a pure helper in `invoices/utils/slugs.py`. It uses Django's `slugify`, so it handles accent stripping, lowercasing and hyphenation the same way the rest of the codebase does.
2. Add unit tests next to it.
3. There's no model change or migration. Making slugs unique per invoice would need a model field, so I've left that out for now (see the note at the end).

## Code

`invoices/utils/slugs.py`
```python
from __future__ import annotations

from django.utils.text import slugify

DEFAULT_MAX_LENGTH: int = 80
FALLBACK_SLUG: str = "invoice"


def invoice_title_to_slug(
    title: str | None,
    *,
    max_length: int = DEFAULT_MAX_LENGTH,
    fallback: str = FALLBACK_SLUG,
) -> str:
    """
    Convert an invoice title into an ASCII URL slug.

    - Accents are transliterated ("Lámpara" -> "lampara").
    - Punctuation is dropped; whitespace/underscores become single hyphens.
    - Truncated to ``max_length`` without leaving a trailing hyphen
      or cutting a word in half when avoidable.
    - Returns ``fallback`` if nothing usable remains (e.g. "¿¿??" or "").
    """
    if max_length < 1:
        raise ValueError("max_length must be >= 1")

    # Treat '/', '.', '#' etc. as separators rather than silently gluing words.
    normalized = (title or "").replace("/", " ").replace("_", " ")
    slug = slugify(normalized, allow_unicode=False)

    if len(slug) > max_length:
        cut = slug[:max_length]
        # Prefer breaking at a hyphen so we don't leave half a word.
        if "-" in cut and slug[max_length] != "-":
            cut = cut.rsplit("-", 1)[0]
        slug = cut.strip("-")

    return slug or fallback
```

`invoices/tests/test_slugs.py`
```python
import pytest

from invoices.utils.slugs import invoice_title_to_slug


@pytest.mark.parametrize(
    ("title", "expected"),
    [
        ("Invoice 2026-014", "invoice-2026-014"),
        ("Factura — Lámpara de Diseño", "factura-lampara-de-diseno"),
        ("  Acme   S.L.  (Q3)  ", "acme-sl-q3"),
        ("Consulting/Oct_2026", "consulting-oct-2026"),
        ("#42: Hosting & Support", "42-hosting-support"),
        ("", "invoice"),
        (None, "invoice"),
        ("¿¿??", "invoice"),
    ],
)
def test_invoice_title_to_slug(title: str | None, expected: str) -> None:
    assert invoice_title_to_slug(title) == expected


def test_truncates_on_word_boundary() -> None:
    slug = invoice_title_to_slug("alpha beta gamma delta", max_length=13)
    assert slug == "alpha-beta"
    assert not slug.endswith("-")


def test_hard_cut_when_single_long_word() -> None:
    assert invoice_title_to_slug("a" * 100, max_length=10) == "a" * 10


def test_rejects_invalid_max_length() -> None:
    with pytest.raises(ValueError):
        invoice_title_to_slug("x", max_length=0)
```

```powershell
# -> factura-2026-014-acme-sl-q3
```

**Note:** two invoices with the same title will get the same slug. If the slug goes in URLs, either build the URL with the ID (`/invoices/<id>-<slug>/`, which needs no schema change) or add a unique `slug` field. The field would mean a migration that has to be reviewed, and it should sit behind a flag because it touches billing. I'd suggest the ID-in-URL option.
