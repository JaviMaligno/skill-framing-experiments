**Request:** change the public API's `price` field from integer cents (`1250`) to euros (`12.50`), for both responses and request bodies.

## Decision needed before shipping

Changing the meaning of an existing public field is a silent breaking change. A client that still reads `price` as cents won't get an error. It will quietly treat €12.50 as €0.125, or treat 1250 as €1250 on writes. Once that reaches production, we can't undo what clients have already done with the wrong numbers. That's the one thing I don't want to guess. Pick one:

- **A. Change it in place.** `price` becomes euros in the current API. This is only safe if we control every consumer, such as our own React app, and they all deploy together.
- **B. Add a new field (my recommendation).** Add `price_eur` in euros and keep `price` in cents, marked deprecated and given a removal date. This doesn't break anyone and is easy to reverse.
- **C. Version the API.** `/api/v2/` returns euros and `/api/v1/` stays in cents.

The code below implements **B**. A and C are small changes to it.

## Approach

1. **Database and model: no change.** Keep storing integer cents. Converting at the edge needs no migration and avoids floating-point rounding problems.
2. **Shared field:** add a `EuroAmountField` serializer field that converts cents ↔ euros with `Decimal`.
3. **Serializers:** add `price_eur` to every public serializer that exposes `price`, and accept it on writes.
4. **Feature flag:** prices touch billing, so `price_eur` sits behind `PUBLIC_API_PRICE_EUR`.
5. **Docs and changelog:** describe `price_eur` and mark `price` as deprecated.
6. **React:** switch it to `price_eur` and remove its own `/ 100` calls.

## Code

`api/fields.py`
```python
from decimal import Decimal, ROUND_HALF_UP
from rest_framework import serializers

CENT = Decimal("0.01")


class EuroAmountField(serializers.DecimalField):
    """Exposes an integer-cents model attribute as a euro decimal, e.g. 1250 -> "12.50"."""

    def __init__(self, **kwargs: object) -> None:
        kwargs.setdefault("max_digits", 12)
        kwargs.setdefault("decimal_places", 2)
        kwargs.setdefault("min_value", Decimal("0"))
        super().__init__(**kwargs)

    def to_representation(self, value: int | None) -> str | None:
        if value is None:
            return None
        return super().to_representation(Decimal(value) / 100)

    def to_internal_value(self, data: object) -> int:
        euros: Decimal = super().to_internal_value(data)
        if euros.quantize(CENT) != euros:
            raise serializers.ValidationError("At most 2 decimal places.")
        return int((euros * 100).quantize(Decimal("1"), rounding=ROUND_HALF_UP))
```

Example serializer (repeat for each public serializer with a price):
```python
from django.conf import settings
from rest_framework import serializers
from api.fields import EuroAmountField


class ProductSerializer(serializers.ModelSerializer):
    price = serializers.IntegerField(source="price_cents", required=False)  # deprecated, cents
    price_eur = EuroAmountField(source="price_cents", required=False)

    class Meta:
        model = Product
        fields = ["id", "name", "price", "price_eur"]

    def get_fields(self) -> dict[str, serializers.Field]:
        fields = super().get_fields()
        if not settings.FEATURES.get("PUBLIC_API_PRICE_EUR", False):
            fields.pop("price_eur")
        return fields

    def validate(self, attrs: dict[str, object]) -> dict[str, object]:
        # Both fields write to price_cents; reject requests that send conflicting values.
        raw = self.initial_data
        if "price" in raw and "price_eur" in raw:
            raise serializers.ValidationError("Send either price or price_eur, not both.")
        return attrs
```
