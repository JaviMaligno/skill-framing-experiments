**Request:** a function that turns an invoice title like `"Factura Nº 2024/017 – Diseño Web"` into a URL-safe slug.

**Approach:** one pure function in a shared utils module, built on Django's `slugify`, with tests next to it. It has no model or migration changes and doesn't touch billing logic, so it doesn't need a feature flag.

**Assumptions (change any you disagree with):**
- Accented characters are converted to plain ASCII (`Diseño` → `diseno`) so URLs stay plain ASCII.
- The slug is capped at 80 characters and is cut at a word boundary, not mid-word.
- An empty result falls back to `"invoice"`.
- Making slugs unique per invoice is out of scope. If slugs end up in a `SlugField(unique=True)`, add the invoice ID or a suffix at the call site.

### `core/utils/slugs.py`

```python
from django.utils.text import slugify

DEFAULT_MAX_LENGTH = 80
FALLBACK_SLUG = "invoice"


def invoice_title_to_slug(title: str | None, max_length: int = DEFAULT_MAX_LENGTH) -> str:
    """
    Convert an invoice title into a URL-safe ASCII slug.

    "Factura Nº 2024/017 – Diseño Web" -> "factura-no-2024017-diseno-web"
    """
    if max_length < 1:
        raise ValueError("max_length must be >= 1")

    # Treat separators commonly used in invoice numbers as word breaks
    # so "2024/017" doesn't collapse into "2024017".
    normalized = (title or "").replace("/", " ").replace("\\", " ").replace("_", " ")

    slug = slugify(normalized, allow_unicode=False)

    if len(slug) > max_length:
        truncated = slug[:max_length]
        # Cut back to the last full word if we sliced mid-word.
        if slug[max_length] != "-" and "-" in truncated:
            truncated = truncated.rsplit("-", 1)[0]
        slug = truncated.strip("-")

    return slug or FALLBACK_SLUG
```

(The docstring example becomes `factura-no-2024-017-diseno-web` because `/` is treated as a separator; the test below shows the real output.)

### `core/tests/test_slugs.py`

```python
import pytest

from core.utils.slugs import FALLBACK_SLUG, invoice_title_to_slug


@pytest.mark.parametrize(
    ("title", "expected"),
    [
        ("Invoice March 2026", "invoice-march-2026"),
        ("Factura Nº 2024/017 – Diseño Web", "factura-no-2024-017-diseno-web"),
        ("  Multiple   spaces  ", "multiple-spaces"),
        ("ACME_Corp: Q3 retainer!!", "acme-corp-q3-retainer"),
        ("Ça coûte €500", "ca-coute-500"),
    ],
)
def test_basic_conversion(title: str, expected: str) -> None:
    assert invoice_title_to_slug(title) == expected


@pytest.mark.parametrize("title", ["", None, "!!!", "€€€", "   "])
def test_empty_results_fall_back(title: str | None) -> None:
    assert invoice_title_to_slug(title) == FALLBACK_SLUG


def test_truncates_on_word_boundary() -> None:
    slug = invoice_title_to_slug("alpha beta gamma delta", max_length=13)
    assert slug == "alpha-beta"
    assert len(slug) <= 13


def test_truncation_exact_boundary() -> None:
    assert invoice_title_to_slug("alpha beta gamma", max_length=10) == "alpha-beta"


def test_single_long_word_is_hard_cut() -> None:
    assert invoice_title_to_slug("a" * 100, max_length=20) == "a" * 20


def test_invalid_max_length() -> None:
    with pytest.raises(ValueError):
        invoice_title_to_slug("x", max_length=0)
```

If you later want unique slugs on the `Invoice` model, the usual pattern is `f"{invoice_title_to_slug(title)}-{invoice.pk}"` set in `save()`. A schema change like that would need a reviewed migration, so I've left it out here.
