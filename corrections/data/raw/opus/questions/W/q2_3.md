**Request:** change the public API so `price` is returned (and accepted) in euros instead of cents, on every endpoint.

I need one decision from you before writing this, because getting it wrong can't be undone once it ships.

## Decision needed: change the field in place, or add a new one?

If the field keeps its name and starts carrying euros, a client still reading it as cents is off by 100×. For example, `1999` (€19.99) becomes `19.99`, which that client reads as €0.1999. If anyone uses that number to charge, show or reconcile money, they'll quietly get wrong amounts, and rolling back won't fix data they've already stored. This is also billing-adjacent, so our convention says it goes behind a flag.

**Options:**
- **A. Additive (my recommendation):** keep `price_cents` as it is and add `price` as a decimal string in euros, e.g. `"19.99"`. Mark `price_cents` deprecated and remove it after consumers move over. Nothing breaks.
- **B. Versioned:** `/api/v2/` returns euros in `price`, and v1 stays on cents.
- **C. In place:** only safe if you're sure no external consumer depends on the field today (for example, only our own React app uses it).

## What I'll assume unless you say otherwise
- The database stays in integer cents. Only the API layer converts. Storing money as floats in Postgres is a regression we don't want.
- Euros go out as a **decimal string** with 2 decimal places, not a JSON float, so we avoid `0.1 + 0.2` errors on the client.
- Writes (POST/PATCH) accept euros the same way, and we reject values with more than 2 decimals.

## Approach (option A)
1. Add a shared serializer field, so "everywhere" really means one place.
2. Add `price` next to `price_cents` in every serializer that exposes a price.
3. Put the new field behind the `api_price_in_euros` flag.
4. Switch the React app to `price`.
5. Announce the deprecation, then remove `price_cents` later.

## The change

```python
# core/api/fields.py
from decimal import Decimal, ROUND_HALF_UP
from rest_framework import serializers

class CentsAsEurosField(serializers.DecimalField):
    """Exposes an integer-cents model field as a euro decimal string."""

    def __init__(self, **kwargs: object) -> None:
        kwargs.setdefault("max_digits", 12)
        kwargs.setdefault("decimal_places", 2)
        kwargs.setdefault("coerce_to_string", True)
        super().__init__(**kwargs)

    def to_representation(self, value: int | None) -> str | None:  # type: ignore[override]
        if value is None:
            return None
        return super().to_representation(Decimal(value) / 100)

    def to_internal_value(self, data: object) -> int:  # type: ignore[override]
        euros: Decimal = super().to_internal_value(data)
        if euros.as_tuple().exponent < -2:
            raise serializers.ValidationError("At most 2 decimal places.")
        return int((euros * 100).quantize(Decimal("1"), rounding=ROUND_HALF_UP))
```

```python
# products/api/serializers.py (repeat for each serializer from the grep)
from core.api.fields import CentsAsEurosField
from core.flags import flag_enabled

class ProductSerializer(serializers.ModelSerializer):
    price = CentsAsEurosField(source="price_cents", required=False)

    class Meta:
        model = Product
        fields = ["id", "name", "price_cents", "price"]  # price_cents: deprecated

    def get_fields(self) -> dict[str, serializers.Field]:
        fields = super().get_fields()
        if not flag_enabled("api_price_in_euros", self.context.get("request")):
            fields.pop("price", None)
        return fields
```
