## What I assumed
- `/reports` is a React page that loads data from a DRF endpoint, `GET /api/reports/`, backed by a `Report` model with a `created_at` field.
- **Page-number pagination**, 25 per page by default, capped at 100. Users can jump to a page, and the number goes in the URL (`?page=3`). If the table grows to millions of rows or new reports are added very often, cursor pagination would suit it better.
- **Newest reports first.** Pagination needs a fixed sort order, so I added `-id` as a tiebreaker.
- **Not billing-related**, so no feature flag.
- If `/reports` is actually a server-rendered Django template, the backend part is the same idea using Django's `Paginator` / `ListView.paginate_by`. Tell me and I'll rewrite it that way.

## Approach (in order)
1. Backend: add a pagination class and use it in the reports list view. Change the view to fetch only the fields the list shows.
2. Add an index on `(created_at, id)`. The page sort uses it, and the `COUNT` stays cheap. This goes through migration review.
3. Front end: read the paginated response, show Prev/Next, and keep the page number in the URL.

## 1. Backend

`reports/pagination.py`
```python
from rest_framework.pagination import PageNumberPagination


class ReportPagination(PageNumberPagination):
    page_size: int = 25
    page_size_query_param: str = "page_size"
    max_page_size: int = 100
```

`reports/views.py`
```python
from django.db.models import QuerySet
from rest_framework import generics

from .models import Report
from .pagination import ReportPagination
from .serializers import ReportListSerializer


class ReportListView(generics.ListAPIView):
    serializer_class = ReportListSerializer
    pagination_class = ReportPagination

    def get_queryset(self) -> QuerySet[Report]:
        return (
            Report.objects
            .select_related("created_by")          # adjust to the FKs the serializer touches
            .only("id", "title", "status", "created_at", "created_by__name")
            .order_by("-created_at", "-id")
        )
```

The response changes from a plain list to:
`{"count": 1234, "next": "...?page=3", "previous": "...?page=1", "results": [...]}`.

## 3. Front end

`src/pages/Reports.tsx`
```tsx
import { useEffect, useState } from "react";
import { useSearchParams } from "react-router-dom";

type Report = { id: number; title: string; status: string; created_at: string };
type Page<T> = { count: number; next: string | null; previous: string | null; results: T[] };

const PAGE_SIZE = 25;

export default function Reports() {
  const [params, setParams] = useSearchParams();
  const page = Math.max(1, Number(params.get("page")) || 1);
  const [data, setData] = useState<Page<Report> | null>(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    const ctrl = new AbortController();
    setLoading(true);
    fetch(`/api/reports/?page=${page}&page_size=${PAGE_SIZE}`, { signal: ctrl.signal })
      .then((r) => r.json())
      .then(setData)
      .catch((e) => e.name !== "AbortError" && console.error(e))
      .finally(() => setLoading(false));
    return () => ctrl.abort();
  }, [page]);

  const totalPages = data ? Math.max(1, Math.ceil(data.count / PAGE_SIZE)) : 1;
  const go = (p: number) => setParams({ page: String(p) });

  return (
    <div>
      {loading && <p>Loading…</p>}
      <table>{/* existing row rendering, now over data?.results ?? [] */}</table>
      <nav aria-label="Reports pagination">
        <button disabled={!data?.previous} onClick={() => go(page - 1)}>Previous</button>
        <span> Page {page} of {totalPages} ({data?.count ?? 0} reports) </span>
        <button disabled={!data?.next} onClick={() => go(page + 1)}>Next</button>
      </nav>
    </div>
  );
}
```
If the page uses React Query or SWR, put the same `page` key into that hook instead of the `useEffect`.

## How to check it works
- **API:** `curl "localhost:8000/api/reports/?page=2"` should return 25 results, a `count`, and working `next`/`previous` links. `?page=9999` should return a 404. On the front end that shows as an empty page, so add a "go to last page" fallback if you want one.
- **Query:** turn on Django Debug Toolbar or `connection.queries`. You should see one `COUNT` plus one `SELECT … LIMIT 25 OFFSET …`, and no extra query per row.
- **Index:** run `EXPLAIN ANALYZE` on the page query in staging. It should use `report_created_id_idx` instead of a full table scan with a sort.
- **UI:** load `/reports`, step through the pages, refresh on page 3 (it should stay on page 3), and use the browser Back button (it should go back a page).
- **Tests:** add one API test that creates 30 reports and checks that page 1 has 25, page 2 has 5, and the order is newest first.
