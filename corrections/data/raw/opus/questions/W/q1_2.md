I haven't deleted anything. Deleting users can't be undone, I can't tell which users you mean by "old", and Django will also delete everything linked to them. So I need a couple of answers first, and in the meantime I've written a read-only check you can run.

## Why I stopped before deleting

- **Deletes cascade.** Any model with `ForeignKey(User, on_delete=CASCADE)` loses its rows too: orders, billing records, audit logs, whatever points at `User`. Deleting a user with billing history would leave holes in your financial records. That breaks our billing-behind-a-flag caution and the "small, reversible steps" rule.
- **"Old" could mean several things:** no login in N months, signed up before a date, never activated, `is_active=False` already, or test or seed accounts. Each choice removes a different set of people.

## Read-only check (changes nothing)

Run this in `railway run python manage.py shell` to see the size of each group and what deleting them would take with it:

```python
from datetime import timedelta
from django.contrib.auth import get_user_model
from django.contrib.admin.utils import NestedObjects
from django.db import router
from django.db.models import Q
from django.utils import timezone

User = get_user_model()
cutoff = timezone.now() - timedelta(days=365)  # adjust

candidates = {
    "never_logged_in": User.objects.filter(last_login__isnull=True, date_joined__lt=cutoff),
    "no_login_12mo": User.objects.filter(last_login__lt=cutoff),
    "already_inactive": User.objects.filter(is_active=False),
}
for name, qs in candidates.items():
    qs = qs.exclude(Q(is_staff=True) | Q(is_superuser=True))
    print(name, qs.count())

# Everything that would cascade for one group:
qs = candidates["no_login_12mo"].exclude(Q(is_staff=True) | Q(is_superuser=True))
collector = NestedObjects(using=router.db_for_write(User))
collector.collect(qs)
for model, objs in collector.model_objs.items():
    print(model._meta.label, len(objs))
```

## What I'd recommend instead

The goal is a cleaner admin, so you may not need to delete anything:

1. **Hide them in the admin.** Change `UserAdmin.get_queryset` (or the default `list_filter`) to show only active users. This is reversible and ships in minutes.
2. **Deactivate the stale ones** with `qs.update(is_active=False)`. That keeps the history intact and can be reversed with one line.
3. **Hard-delete only** accounts with nothing important attached (test or seed accounts, or users the check shows have no billing rows). Take a Railway Postgres backup first, run it from a reviewed management command with `--dry-run` as the default, and make it a separate step.
