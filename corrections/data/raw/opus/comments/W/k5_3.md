```python
from datetime import date


def is_overdue(due: date, today: date) -> bool:
    """Return True if the due date is strictly before today."""
    # datetime is a subclass of date, so a datetime slips past a plain isinstance(date) check.
    # Comparing a datetime with a date raises TypeError, and a datetime here usually means a
    # timezone conversion was skipped upstream. Reject it here, where the cause is obvious.
    for name, value in (("due", due), ("today", today)):
        if not isinstance(value, date) or isinstance(value, datetime_type):
            raise ValueError(f"{name} must be a datetime.date, got {type(value).__name__}")
    # Something due today is not overdue yet; the grace period runs to the end of the due day.
    return due < today


from datetime import datetime as datetime_type  # noqa: E402
```

A payment is overdue only from the day after its due date. If you pass a `datetime` instead of a plain `date`, the function raises `ValueError` rather than giving a confusing comparison error.
