You want old users removed from production to declutter the admin.

Before any destructive change, what defines “old”—signup date, last login, or inactive status? Should staff accounts and users with billing records be excluded?

I’d first count and preview matching accounts, review related records that deletion could affect, and confirm a backup before deleting. Afterward, verify the affected count and retained accounts.

If this is only admin clutter, filtering inactive users out of the default view is safer and reversible.
